게임(로스트아크) 파티 구성 시 악성 유저를 자동으로 걸러내는 풀스택 웹 서비스. React 프론트엔드 · Spring Boot 병렬 처리 백엔드 · Python FastAPI AI OCR 마이크로서비스 3개 서비스 레이어를 처음부터 단독 설계·구현.

Spring Boot 백엔드 — 병렬 처리 최적화
  • 병렬 처리 구조 설계: 캐릭터 6개 × 15페이지 × 본문 확인 = 수백 건 외부 HTTP 요청 문제 분석. sterm 파라미터가 +10,000 단위로 규칙적으로 증가함을 파악 → 나머지 14페이지 URL 선계산 후 CompletableFuture 동시 요청으로 전환.
  • 목적별 ThreadPool 3개 분리 운영: 페이지 fetch 전용, 게시글 본문 확인 전용(×10), 부캐 검색 전용(×6) — 전체 강화 검색 수 분 → 수 초.
  • 크롤링 신뢰도 확보: stype=content 검색의 오탐 문제를 개별 게시글 fetch 후 "대상자:" 섹션 내 닉네임 존재 여부 정밀 검증으로 해결. 실사용자 제보 기반 5가지 분리자 패턴 오탐 방지 로직 구현.
  • Lost Ark Open API 연동으로 부캐 자동 조회 — 닉네임 → 캐릭터 6개 병렬 검색.
  • WireMock 기반 통합 테스트 — 외부 의존성 없이 크롤링·파싱 로직 검증.
Python AI OCR 마이크로서비스
  • OCR 엔진 선택: Tesseract.js(브라우저, 한국 게임 폰트 인식 부족) → EasyOCR(범용 모델 한계) 시도 후 PaddleOCR PP-OCRv4 한국어 특화 모델 채택. Windows oneDNN 충돌로 버전 2.7.x 고정.
  • 전처리 파이프라인 설계: HSV 마스크로 흰색 픽셀 추출·반전 처리 → 한국 게임 UI 특성에 맞는 인식률 확보.
  • 위치 기반 3단계 닉네임 추출 전략: ①Lv.XX 오른쪽 탐색 → ②서버명 아래 탐색 → ③행 클러스터 탐색 (최후 폴백) 순차 적용.
  • 자모 혼동 오인식 보정: ㅣ↔ㅓ 등 OCR 오인식 패턴 분석 후 후보 닉네임 생성 로직 구현.
React 프론트엔드
