AI Agent Workflow

Claude Code 실전 워크플로우 적용

로스트아크 인벤 체커 개인 프로젝트(Spring Boot + React + Python AI OCR 멀티 서비스)를 개발하면서 Claude Code의 AI 에이전트 기능을 단순 코드 생성 도구가 아닌 개발 워크플로우의 핵심 협업 파트너로 활용했습니다.

"AI 에이전트는 명령을 내리는 도구가 아니라, 함께 설계하고 검증하는 파트너다."
이 관점에서 컨텍스트 관리 · 계획 우선 실행 · TDD 루프 · WAT 프레임워크를 멀티 서비스 프로젝트 전반에 걸쳐 일관되게 적용했습니다. 그 결과 혼자서 3개 언어(Java · TypeScript · Python) + 3개 서비스 레이어를 동시에 관리할 수 있었습니다.
📋
치트시트 기법 2-1. Plan Mode 먼저
기능 구현 전 반드시 Plan Mode
OCR 파이프라인, Spring 병렬 처리, Document PiP 오버레이 등 각 기능을 구현하기 전 Shift+Tab으로 Plan Mode 진입. Claude가 제시한 계획을 검토·수정한 뒤 Accept Mode로 전환하는 루틴을 일관되게 적용. 특히 PaddleOCR 3단계 위치 추출 전략 설계 시 잘못된 초기 가정을 Plan 단계에서 바로잡아 불필요한 리팩토링을 방지.
실제 적용 사례
OCR 닉네임 추출 로직 설계 시 → Plan Mode에서 3단계 전략(Lv.XX 우측 / 서버명 하단 / 행 클러스터) 검토 후 구현 진행
🧠
치트시트 기법 1-1. Second Brain & /memory
프로젝트 기관 기억(Institutional Memory) 구축
멀티 서비스 프로젝트 특성상 세션이 바뀌어도 컨텍스트가 끊기지 않도록 ~/.claude/projects/…/memory/MEMORY.md에 핵심 결정 사항을 기록. "sterm 파라미터 +10,000 패턴 발견", "PaddleOCR 2.7.x 버전 고정 이유", "canvas ref null 버그 해결책" 등 도메인 지식을 누적해 매 세션 재설명 비용 제거.
실제 기록 예시
## OCR 엔진 선택 결정
- PaddleOCR 2.7.x 고정: Windows oneDNN 충돌
- Tesseract.js 탈락: 한국 게임 폰트 인식률 부족

치트시트 기법 1-2. Lazy Loading CLAUDE.md
서비스별 컨텍스트 분리로 토큰 최적화
Spring Boot / React / Python OCR 3개 서비스를 각 폴더별 CLAUDE.md로 분리. CLAUDE.md에는 참조만, 상세 내용은 별도 파일로 관리해 각 서비스 작업 시에만 해당 컨텍스트가 로드되도록 설계. 불필요한 토큰 소비 없이 서비스 전환 시 집중도 유지.
폴더 구조 적용
backend/CLAUDE.md → @docs/api-design.md 참조만
ocr-service/CLAUDE.md → @docs/ocr-pipeline.md 참조만
🔄
치트시트 기법 2-2. TDD 기반 스마트 코딩
작은 변경 → 테스트 → 린트 → 커밋 루프
크롤링·파싱 로직에 WireMock 기반 통합 테스트를 먼저 작성하고 Claude와 함께 구현하는 TDD 방식 적용. "대상자: 섹션 오탐 방지", "5가지 분리자 패턴 처리" 등 실사용자 제보로 발견된 엣지케이스도 테스트 → 구현 순서로 안전하게 반영. 문제 발생 시 마지막 커밋으로 즉시 복귀 가능.
핵심 루프
WireMock 테스트 작성 → Claude 구현 → mvn test → 커밋 → 다음 케이스
✅
치트시트 기법 2-6. 로컬 TODO.md 활용
TODO.md로 멀티 서비스 작업 연속성 유지
Spring Boot · React · Python 3개 서비스를 병렬로 개발하면서 TODO.md로 전체 작업 흐름을 관리. 세션 시작 시 "TODO.md 읽고 첫 번째 항목부터 시작"으로 지시, 세션 종료 시 "TODO.md 업데이트해줘"로 진행 상황 자동 반영. 여러 세션에 걸쳐도 작업 연속성을 완벽하게 유지.

치트시트 기법 2-3. Thinking 로그 · 2-5. 에러 그대로
AI의 추론 과정 모니터링 + 에러 원문 투입
Thinking 로그를 통해 Claude가 잘못된 가정을 하는 순간 즉시 Escape로 중단. 특히 OCR 엔진 비교 과정에서 EasyOCR을 채택하려는 방향을 초반에 차단하고 한국 게임 폰트 특성에 맞는 PaddleOCR로 재방향 설정. 스택 트레이스는 해석 없이 에러 로그 원문 그대로 Claude에 투입해 정보 손실 없이 디버깅.

WAT Framework 적용

🤖 OCR 엔진 선택 과정
  • Tesseract.js (브라우저) — 한국 게임 폰트 인식률 부족으로 탈락
  • EasyOCR (Python) — 범용 모델, 한글 정확도 한계로 탈락
  • PaddleOCR PP-OCRv4 — 한국어 특화 모델 채택. Windows oneDNN 충돌로 2.7.x 버전 고정
🎯 위치 기반 3단계 추출 전략
  • 전략 1: Lv.XX 텍스트 우측 동일 Y좌표 탐색
  • 전략 2: 서버명(8개 제외 목록) 하단 동일 X열 탐색
  • 전략 3: Y좌표 기준 행 클러스터 분류 후 탐색 (최후 폴백)
